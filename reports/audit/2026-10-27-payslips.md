# Bulk payslips — implementation and verification (2026-10-27)

## Feature

Admins upload payslip PDFs in bulk; each guard gets only their own slip in the web guard portal and the Android app.

**Data model** — `payslipDocuments/{id}`: employeeDocId, employeeId, employeeName, clientName, period (`YYYY-MM`), fileName, storagePath (`employees/{doc}/payslips/{period}/{uuid}.pdf`), sizeBytes, uploadedBy, parseMethod. Server-only in Firestore rules; `employees/*/payslips/**` is explicitly denied to clients in Storage rules.

**Admin API** — `POST /api/admin/payslips/upload` (multipart: `period`, `files` 1–50 × ≤10 MB, optional `dryRun`). Each PDF is parsed for a `CISS/<client>/<year>/<serial>` id (serial may be alphanumeric), then filename id, then a bare 6–12 digit serial corroborated by the printed name, then a unique full-name match. Ambiguous, unmatched, multi-employee and incompletely-inspected PDFs are reported and **never stored**. A PDF containing more than one distinct employee id is refused (`multiple-employees`), as is a file whose pages/text exceed the inspection limits (`incomplete-pdf`). `GET /api/admin/payslips?period=` lists recent uploads.

**Guard API** — `GET /api/guard/payslips` (own employeeDocId only, sorted in memory), `GET /api/guard/payslips/{id}/payslip` (ownership re-checked, storage path constrained to the caller's prefix, streamed as `application/pdf` attachment). Leave and payroll cycles remain retired (410).

**UI** — `/settings/payslips` (period + multi-file picker, per-file saved/unmatched/errors), `/guard/payslips` (list + download); navigation entries restored. Flutter: `PayslipDocumentModel`, repository `fetchPayslips`/`downloadPayslipPdf`, payslip screen, dashboard tile and shell entry; `payslips` re-enabled in module flags while `leave` stays removed. Downloads save a temp PDF and open it (share fallback) with 60 s download / 15 s write timeouts.

## PENTA review findings and fixes

| Finding | Fix |
|---|---|
| A PDF containing two employees' slips was attributed to the first id | Extract **all** distinct ids and refuse the file (`multiple-employees`); regression test |
| Name index scanned only 1,000 employees, so a duplicate outside the cap could misattribute | Paginate the entire employee collection (500/page, 50k cap); if the cap is hit, refuse name-only attribution |
| Admin UI rendered error objects as React children | Errors typed `{fileName,message}` and rendered as strings |
| Extraction read only the first 3 pages, so a second employee on page 4 could be delivered | Inspect every page within 50 pages / 200k chars; return `complete:false` and refuse the upload when limits are exceeded |
| Underscore filename parser accepted a numeric prefix (`871` from `871A`) | Capture the complete alphanumeric serial with an identifier boundary; tests for `A871` and `871A` |
| Work-order commit accepted impossible dates and crashed on empty dates | `normalizeDutyDate` strict calendar validation (rejects 2026-02-30, 2025-02-29), trims input, persistent invalid flag, 400 before any write |
| A PDF with two employees' names/resource ids but no full CISS ids could be attributed to the first | Resolve every labelled name and standalone id against employees; refuse when the evidence points at more than one employee (`multiple-employees`) |
| Full-id-vs-name and filename-id-vs-name conflicts were not cross-checked | Unify PDF id, filename id, filename name, every labelled name and every standalone id into one evidence set before attribution; refuse on conflict |
| Evidence was truncated to 10 items, hiding a later employee | No truncation; more than 20 identifiers is refused (`evidence-limit`) rather than partially read |

## Limitations

- Image-only/scanned or encrypted PDFs have no text: they are refused as unmatched (rename with the employee id or OCR them).
- Re-uploading the same period creates a new document (newest wins); old Storage objects are not pruned.
- The Flutter notification deep-link for `payslip` was not restored (the push contract belongs to the web owner).
- No live Firebase/GCP/Vercel calls; rules were tested statically, not deployed.
